质保年限维护

按合同需求类型 + 财务主体维护默认质保年限，用于计算合同"质保期满日"（竣工日 + N 年）。过渡方案——业务系统结构化承接质保年限之前由财务中台维护。

业务规则：

  • 合同签订时业务系统按此配置写入默认质保年限，业务侧可基于合同条款单独调整。
  • 取哪条规则：按项目签单日落入启用中规则的生效开始日~结束日区间匹配（与计提比例同一套口径），且合同所属财务主体须在该规则适用范围内。
  • 质保期满日 = 竣工日 + N 年（例：2024-08-15 竣工 + 2 年 = 2026-08-15）；期满次月起停止计提，若余额 > 0 则质保期满月执行转回。
  • 唯一性校验：以合同需求类型为配置基准，按"需求类型 + 每个被勾选的财务主体"逐一校验时间段不重叠；已禁用行不占唯一性名额，允许历史留痕。
  • 规则调整采用"手工调整旧规则的生效结束日 + 新增新规则"两步流程（不做自动截断）：先编辑旧行填生效结束日，再新增新行、生效开始日 = 旧结束日次日；旧规则的质保年限值不允许直接改。
  • 禁用 vs 调整生效结束日：日常"到期换规则 / 计划性下线"用编辑生效结束日；"这条建错了 / 立即整条作废"用禁用，禁用即刻不参与匹配、可再启用。
  • 唯一性校验时机：新增保存、编辑保存（针对启用中的行）、启用动作均触发；已禁用行编辑保存不校验。
  • 期满日双态语义——修改配置不回滚已入账凭证，但期满日按合同状态区分：计提中合同的期满日是动态推导值（每次跑批按当下启用中规则重算），改配置即刻在下次转回跑批生效；计提结束合同的期满日已在触发转回时凝固为转回单快照，之后永不变动。
